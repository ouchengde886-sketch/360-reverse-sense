## 三、快速上手

### 3.0 真实病毒查杀引擎（推荐用于免杀验证）

**这是真正的查杀引擎调用**，会加载 360 的特征库并解析 PE 文件，给出 `clean`/`threat` 判定。
与 3.1 的"签名信誉查询"不同 —— 那个只查证书链，不跑查杀引擎。

```python
from av360_sense import AV360Sense

s = AV360Sense()

# AVE 特征引擎（本地特征库比对）
r = s.scan_ave(r"C:\samples\payload.exe")
print(r)
# {'path': ..., 'verdict': 'clean'|'threat'|'engine_error', 'status': 0, 'cfg': '6/6'}

# QVM AI 引擎状态（机器学习判定未知木马，免杀对抗最关键）
print(s.qvm_state())
# {'ok': True, 'bole_init': '0', 'features_init': '0', 'version': 5}

# 多引擎联合查杀（AVE + 云安全 + QEX/启发式官方引擎）
r = s.scan_all_engines(r"C:\samples\payload.exe")
print(r["verdict"])          # 聚合判定
print(r["engines"]["ave"])   # AVE 特征引擎通道
print(r["engines"]["cloud"]) # 云端信誉通道
print(r["engines"]["official"])  # 官方引擎通道（含引擎归属）

# 读取 360 官方扫描结果（含每条威胁由哪个引擎判定）
log = s.scan_log_latest()
print(log["engines"])   # ['360云查杀引擎（本地木马库）', '360启发式引擎', 'QEX脚本查杀引擎']
for t in log["threats"]:
    print(t["engine"], t["verdict"], t["path"])
```

判定含义：
- `clean` —— 合法 PE 且未命中特征库
- `threat` —— 命中特征库（`name` 字段给出威胁名）
- `engine_error` —— **非 PE 文件**（如 txt/bin/EICAR/ps1/zip），AVE 引擎不处理

**重要**：AVE 引擎**只处理 PE**。脚本（`.ps1`/`.vbs`/`.js`/`.bat`）、
压缩包（`.zip`/`.rar`）等非 PE 文件由 **QEX 脚本引擎**和**云安全引擎**负责，
这两条通道通过 `official`（360 官方扫描日志）接入。
因此判定脚本类样本必须用 `scan_all_engines()`，不能只用 `scan_ave()`。

### 3.0.1 处理威胁

**查杀之后怎么处理病毒** —— 三种粒度：

```python
# 1) 处理最近一次 360 官方扫描发现的所有威胁
s.handle_scan_log(action="quarantine")          # 移入隔离区（可恢复）
s.handle_scan_log(action="delete")              # 直接删除
s.handle_scan_log(action="rename")              # 原地改名为 .vir
s.handle_scan_log(action="none")                # 只记录不动手
s.handle_scan_log(dry_run=True)                 # 试运行，列出将处理的文件

# 2) 处理单个文件
s.handle_threat(r"C:\samples\payload.exe", action="quarantine")

# 3) 查杀 + 自动处理（多引擎）
s.scan_and_handle(r"C:\samples\payload.exe", action="quarantine")
```

命令行：

```bash
python av360_sense.py handle --dry-run              # 看会处理哪些
python av360_sense.py handle --action quarantine    # 真处理
```

#### ⚠️ 测试时必须用 `copy_only`

默认 `quarantine` 是**移动**文件，原路径会消失 —— 反复测试会越跑越少。
测试场景请用 `copy_only=True`，它**只复制不移动**，原文件保留：

```python
# 测试模式：隔离副本，原文件不动
s.handle_scan_log(action="quarantine", copy_only=True,
                  quarantine_dir=r"C:\test\quarantine")
```

```bash
python av360_sense.py handle --copy-only --action quarantine --dir C:\test\quarantine
```

已验证：复制模式下 5 个样本全部隔离成功，**MD5 与原文件完全一致**，
且 D:\troyr2 下 5 个原文件全部保留。

隔离目录会写 `_manifest.txt`，记录时间、原路径、隔离路径、以及
`copied`（复制，原文件保留）/ `moved`（移动，原文件已移除）。

#### 处理动作实测结果

| 模式 | 原文件 | 隔离副本 | 适用 |
|---|---|---|---|
| `copy_only=True` | **保留** | MD5 一致 | **测试**（可反复跑）|
| `copy_only=False` | 移除 | MD5 一致 | 生产（真正清理）|

360 的自我保护**不拦截**对普通文件的删除/改名（已实测）。
它只保护自己的安装目录。

### 3.2 实时感知（免杀自动化核心）

```python
from av360_sense import AV360Sense

s = AV360Sense()

# 启动监听，然后在另一线程/进程里运行样本
for ev in s.watch(seconds=60):
    if ev.kind in ("popup", "popup_detail"):
        print(f"[弹窗] {ev.title}")
        print(f"       动作={ev.action} 判定={ev.verdict} 路径={ev.path}")
        print(f"       正文={ev.body}")
    elif ev.kind == "scan_hit":
        print(f"[查杀] {ev.path} 动作={ev.action} 规则={ev.rule} MD5={ev.extra.get('md5')}")
    elif ev.kind == "process":
        print(f"[进程] {ev.title} {ev.body}")
```

## 四、事件模型

所有感知结果统一为 `Event`：

| 字段 | 说明 | 示例 |
|---|---|---|
| `kind` | 事件类型 | `popup` / `popup_detail` / `scan_hit` / `process` |
| `source` | 来源模块 | `360hipsPopWnd.dll` / `360ScanLog` |
| `title` | 弹窗标题/摘要 | `360主动防御拦截` |
| `body` | 弹窗正文全文 | `检测到木马程序，已拦截` |
| `path` | 涉及文件路径 | `C:\test\sample.exe` |
| `action` | 处理动作 | `blocked` / `cleaned` / `allowed` / `quarantined` |
| `verdict` | 判定类型 | `trojan` / `virus` / `suspicious` / `risk` |
| `rule` | 规则 ID | `30,3,30-1-2_0_0_1` |
| `hwnd` | 窗口句柄 | `0x26099E` |
| `extra` | 附加字段 | `{"pid": "...", "md5": "..."}` |

## 五、免杀自动化集成范式

```python
from av360_sense import AV360Sense
import threading, time

def test_sample(sample_path):
    """对单个样本做完整的"送检 + 感知"闭环。"""
    s = AV360Sense()
    findings = []

    # 1) 先记录基线状态
    before = s.state()

    # 2) 后台启动感知，同时运行样本
    def run():
        time.sleep(1.5)                      # 等监听就绪
        import subprocess
        subprocess.Popen([sample_path])      # 运行待测样本

    threading.Thread(target=run, daemon=True).start()

    # 3) 感知窗口
    for ev in s.watch(seconds=30):
        findings.append(ev.to_dict())

    # 4) 主动送检
    scan_result = s.scan(sample_path)

    return {
        "sample": sample_path,
        "static": scan_result,
        "events": findings,
        "blocked": any(e["action"] == "blocked" for e in findings),
        "detected": any(e["kind"] == "scan_hit" for e in findings),
    }
```

**判读要点**：

- `blocked=True` → 运行时被主动防御拦截（HIPS 命中）
- `detected=True` → 查杀引擎命中（特征/云查）
- `static.signed=False` → 无数字签名（免杀样本常见特征）
- 两者都为 False → 该样本在本次环境下未被发现

## 六、关于"本机装了 360 被保护，是不是就调不了"

**结论：本机装了 360 反而更好调用，不是更差。** 这一点已在本机实测确认。

### 6.1 为什么"被保护"不影响外部调用

自我保护保护的是**进程/文件/注册表**不被篡改，而外部调用查杀走的是
**加载引擎 DLL** 这条路 —— 这是纯用户态的只读操作，不涉及任何
需要"写入"的动作，因此不会被自保护拦截。

实测（本机真实安装 `C:\Program Files (x86)\360\360Safe`）：

```
探测到的引擎根目录: C:\Program Files (x86)\360\360Safe
查杀结果: 已签名: Microsoft | Microsoft Windows
```

### 6.2 本机安装 vs 离线快照

| | 本机安装 | 离线快照 |
|---|---|---|
| 引擎可调用 | ✅ 实测可用 | ✅ 实测可用 |
| 特征库 | **最新**（随 360 更新） | 导出时刻的版本 |
| 与运行中主动防御一致 | ✅ 是同一套 | ❌ 可能版本不一致 |
| 弹窗/日志感知 | ✅ 真实运行环境 | ❌ 无进程在跑，无弹窗 |

**SDK 已自动优先使用本机安装**（`find_engine_root()`），
探测不到时才回退到快照。你也可以显式指定：

```python
s = AV360Sense(safe_root=r"C:\Program Files (x86)\360\360Safe")
```

### 6.3 哪些操作确实会被自保护挡住

只有**需要修改 360 自身状态**的操作才会被拦：

| 操作 | 是否被拦 | 说明 |
|---|---|---|
| 加载 `cloudcom2.dll` 查杀 | ❌ 不拦 | 纯用户态只读 |
| 枚举 `Q360HIPSClass` 窗口 | ❌ 不拦 | 跨进程读窗口，系统允许 |
| 读扫描日志文件 | ❌ 不拦 | 普通文件读 |
| 读 `safemon` 注册表 | ❌ 不拦 | 普通注册表读 |
| 打开 `\\.\360SelfProtection` | ❌ 不拦 | 实测可打开 |
| `IOCTL 0x22204C` 查询 PID | ❌ 不拦 | 该码在免注册白名单内 |
| `IOCTL 0x222024` 查总状态 | ⚠️ **拦** | 不在白名单 → `err=5` |
| `IOCTL 0x222020` 开关自保护 | ⚠️ **拦** | 不在白名单 → `err=5` |
| 结束 360 进程 | ⚠️ **拦** | 句柄保护（`ObRegisterCallbacks`） |
| 删除 360 安装目录文件 | ⚠️ **拦** | minifilter 文件保护 |

**对免杀自动化的意义**：你需要的四条感知链路
（送检、弹窗、查杀通知、拦截状态）**全部属于"不拦"那一类**，
所以在装有 360 的本机上完全可以正常工作。

### 6.4 本机实测环境说明

本机虽然装了 360，但 `360SelfProtection.sys` **未注册为服务**
（`sc query 360SelfProtection` → `NOT_INSTALLED`），
所以 `0x222020` / `0x222024` 返回失败。这与快照环境的表现一致，
说明**这两条限制来自驱动未加载，而非"本机 vs 快照"的差异**。

已加载的 360 驱动（本机实测）：`360AntiHijack`、`360AntiSteal`、
`360Box64`、`360Camera`、`360FsFlt`、`360netmon`、`360Sensor`（均 Running）。

> 若在**完整安装且自保护驱动已加载**的机器上运行，
> `0x222024` / `0x222020` 应能成功 —— 这一点尚未在真实生效的
> 自保护环境下验证过，建议你在那样的机器上复验一次。

## 七、已知限制（重要，避免误判）

1. **引擎单进程只能调一次**
   `GetFileTrustStateEx` 在同一进程内第二次调用会让进程静默退出。
   SDK 已按"每文件独立进程"实现，**不要自己循环调用同一进程**。

2. **必须 32 位宿主**
   360 引擎全是 x86。SDK 内部固定用
   `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe` 调引擎。

3. **`scan()` 返回的是签名信息，不是"病毒/安全"三态**
   实测 `GetFileTrustState*` 返回签名主体/签发者/证书链。
   数值型判定接口 `QueryFilesEx` 需要特征库就绪（由 360 主程序加载），
   在裸外部进程中返回成功但不写数据。

4. **弹窗感知依赖窗口存在**
   360 的 HIPS 弹窗有自动消失机制。`watch()` 的 `interval` 建议
   ≤0.5 秒，否则可能漏掉短命弹窗。

5. **查杀日志是追加写的**
   SDK 用文件大小变化检测新内容。若 360 轮转/清空日志，
   需要重新调用 `watch()` 建立基线。

6. **本机自保护未完全生效**
   本机 `360SelfProtection.sys` 未注册为服务，故 `0x222020` 开关
   与 `0x36059002` 状态查询返回失败（`360SPTool.exe /disablesp` 同样
   返回 `0x8CA3`）。在完整安装且 360tray 运行的机器上应能成功。
